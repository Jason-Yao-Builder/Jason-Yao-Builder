# Feynman Research Skill

这是一个把**研究深度**和**讲述清晰度**焊在一起的 skill。
不是"搜了一堆资料丢给你"，也不是"凭印象讲个故事"。
是先用并行 subagent 把材料挖扎实，再用建造者+费曼老师的视角，把它讲到让外行也能"哦——原来是这样"。

---

## 灵魂三句话

1. **研究的目的不是堆事实，是定位一个值得回答的问题。**
2. **抽象必须配场景。**讲任何机制时，先想象一个具体的人在具体场景里遇到具体的事。
3. **建造者比观察者更能讲清楚。**面对任何制度/机制，先问"是谁、为什么造它"，再问"它今天长什么样"。

---

## 四步流程

```
       ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
输入 → │  拆解   │ →  │  并研   │ →  │  蒸馏   │ →  │  讲述   │ → 产物
       │ Decompose│    │Research │    │ Distill │    │Narrate  │
       └─────────┘    └─────────┘    └─────────┘    └─────────┘
```

每一步都有明确的产物和质量门槛。下一步的输入只能是上一步合格的产物。

---

## 第一步：拆解（Decompose）

### 目标
把用户给的模糊大命题，切成 **3–6 个独立、不重叠、覆盖完整**的子板块。

### 关键动作

**A. 先和用户校准 1–2 个会改变搜索范围的关键决策**——不是问"你想要什么"（无聊），而是问"加这块要花一倍力气，但报告里这块通常会被批为缺失，你怎么权衡"这种**有取舍有推荐**的二选一。

> AskUserQuestion 时每个 option 的 `description` 要写清楚"选这个意味着什么/不选这个会损失什么"，让用户能在 5 秒内做决策。

**B. 子板块的标准分法**（不是公式，是常用模板）：

| 板块代号 | 通常负责回答 | 典型搜索目标 |
|---|---|---|
| **A 制度/历史演进** | 这东西怎么来的？关键时间节点？现行规则？ | 政策文件、官方公告、维基、学术综述 |
| **B 现状数据** | 现在的规模、参与度、效果数据 | 监管数据、统计公报、行业白皮书 |
| **C 利益相关方行为** | 各方（企业/平台/银行/政府）在做什么？怎么做？ | 媒体调查、行业报道、内部 leak、UGC |
| **D 用户态度与障碍** | 受众真实怎么想？障碍是什么？ | 调研报告、社交媒体真实声音、quote |
| **E 国际/历史对比** | 别人怎么做？历史上类似问题怎么解的？ | 顶刊论文、OECD/世行报告、行业年报 |

不是必须 5 个；可以合并、可以省略、可以加。但**每个板块都要满足三个条件**：
- 能被一个 subagent 独立研究（不依赖另一个板块的产物）
- 有清晰的"完成"标准（具体回答哪几个问题）
- 来源类型可预判（避免分给 subagent 一个无处可搜的任务）

**C. 反模式**：
- ❌ 切成"理论 / 实证"——太抽象，subagent 不知道往哪搜
- ❌ 切成"原因 / 解决方案"——解决方案应该是研究产物，不是研究输入
- ❌ 子板块之间互相依赖（B 必须等 A 完成才能开始）

### 产物
对话里给用户看：5 个子板块 + 每个板块的 1 句话定位。然后用户点头，进第二步。

---

## 第二步：并研（Research）

### 目标
每个子板块派一个 **general-purpose subagent**，**run_in_background: true**，并行执行。

### Subagent Prompt 模板

每一个 subagent 的 prompt 必须包含以下 8 个部分（缺一不可）：

```markdown
你是 [项目名] 研究项目的子任务执行人，研究主题是"[一句话主题]"。
你的子任务 [代号] 是：**[子板块标题]**。今天是 [yyyy-mm-dd]。

# 你要回答的问题
（5–10 个具体问题，每个问题尽量带数字/时间/对象，不要"分析一下 X"这种空话）

# 工作方法
1. 用 mcp__research__search 工具，按子板块类型选择引擎组合：
   - 网页/新闻/政策：["brave", "duckduckgo", "sogou"]
   - 学术论文/研究：["openalex", "crossref"]（需要摘要和引用量时加 "semantic_scholar"）
   - 预印本/CS/经济学工作论文：["arxiv"]
   - 技术社区讨论/真实用户声音：["hackernews"]，配合 brave 加 site:reddit.com
   - 统计数据：["worldbank"]（query 格式 "CHN 指标代码 年份:年份"）
   混合研究可一次传多个引擎，如 ["brave", "openalex", "hackernews"]。
2. 中文政策类查询用 sogou 命中率最高，搭配 brave 兜底英文术语。
3. 找到来源后用 mcp__research__fetchWebContent 抓正文。
4. 找到论文后用 mcp__research__fetchAcademicPaper 获取摘要、引用量、PDF 链接。
5. 需要特定国家/指标的统计数据时用 mcp__research__fetchStatData。
6. 优先来源排序：[针对该子板块定制，例如 "监管文件 > 顶刊 > 财经媒体 > 银行公众号 > UGC"]
7. 每个数据/论断必须有来源，按可信度标注：
   - 🟢 论文/官方文件 — 附文件名或链接
   - 🟡 行业共识/媒体报道 — 附媒体名+发布时间
   - 🔴 推断 — 不能伪装成🟢🟡
8. 核实：核心数字至少 2 个独立来源交叉验证。只有 1 源的，标记为🟡并写明"仅 1 源"。

# 输出
把成品写到 `[绝对路径]/[代号]_[标题].md`，结构：
（给出明确的章节骨架，避免 subagent 自由发挥导致格式不一）

# Summary 回执
完成后回我一段不超过 [N] 字的中文 summary：
- 核心数据/发现
- 哪些交叉验证上了 / 没验证上 / 仅 1 源
- 任何意外发现
不要把整份文档复制回我的对话，文件路径就够了。
```

### 关键纪律

- **不要省略"仅 1 源"标记**——后期写报告时要诚实呈现哪些是确定的、哪些是孤证。
- **不要让 subagent 自己拆任务**——它不知道全局，会切歪。
- **路径绝对化**——relative path 在 subagent 里会跑到奇怪地方。
- **Subagent 之间不要互相依赖**——这一步是并行的，依赖留到第三步处理。

### 产物
N 个 markdown 文件落到指定目录，每个 200–400 行，含清晰章节、可信度标注、来源清单。
对话里只看到每个 subagent 的 100–200 字 summary。

---

## 第三步：蒸馏（Distill）

### 目标
**从所有素材里抽出唯一一句话核心问题**——这句话要能成为整个研究的 north star。

这是整个 skill 最容易被跳过、也最容易被做错的一步。**绝对不能跳。**

### 操作

读完所有 subagent 的 summary（不一定要读全文，summary 已经把最关键的提炼出来了）。然后问自己三个问题：

1. **这些数据合在一起，最反直觉/最有张力的是什么？**
   （例：1.5 亿人开了账户，但 78% 是空的）

2. **这件事不能用最简单的解释打发掉吗？**
   - 不能用"产品不好"打发？→ 那是金融工程问题
   - 不能用"宣传不够"打发？→ 那是营销问题
   - 不能用"穷"打发？→ 那是经济问题
   - 都打发不掉？→ **那它就是行为/制度/认知层面的问题，值得研究。**

3. **能不能用一句话说清楚我们要解决什么？**
   句式参考：
   - "为什么 X 现象存在/不存在？"
   - "在 [约束 A] 下，能不能用 [工具 B] 解决 [问题 C]？"
   - "为什么 [反直觉事实] 会发生？"

### 反模式
- ❌ 把 5 个子板块的总结拼起来当主干（那是综述，不是研究）
- ❌ 主干是"我们要分析 X"（不算问题，是任务描述）
- ❌ 主干太宽（"如何解决养老问题"）或太窄（"为什么张三不缴存"）

### 产物
**一段不超过 80 字的核心问题陈述**，先给用户看一遍，确认后进第四步。

---

## 第四步：讲述（Narrate）—— 费曼式建造者视角

### 灵魂

**讲述不是把研究材料倒出来。是把研究材料嚼碎，重新组织成一栋让外行能爬到顶的楼。**

每一层都建立在上一层之上，没有人能跳层听懂。所以叙事必须从**最底层**开始：**为什么世界上需要这个东西？**

### 八层结构模板

> 不是必须用满 8 层，简单题目可以合并；复杂题目可以拆分。但顺序不能乱。

```
第 0 层：核心问题（主干）
        ↓
第 1 层：为什么世界上需要这个东西
        ↓ （从最原始的需求出发，回到工业化前/技术前/制度前的状态）
第 2 层：基础结构是什么、为什么这么搭
        ↓ （为什么不是别的设计？这个设计在解决什么问题？）
第 3 层：当前结构里各部分长什么样、出了什么问题
        ↓ （理论 → 现实，每一部分对一个具体场景）
第 4 层：这套东西在我们的语境下怎么演变到今天
        ↓ （时间线，关键节点，每个节点配"为什么这时候改"）
第 5 层：现状为什么尴尬
        ↓ （把核心痛点数据放在这里——最多 5-8 个）
第 6 层：别人是怎么解的
        ↓ （对照故事——一定要有反差感）
第 7 层：所以我们要回答的问题是
        ↓ （回到第 0 层，闭环）
```

### 写作的 7 条铁律

1. **抽象必配具体角色**
   每讲一个机制都要给一个名字（"30 岁的小王"、"在便利店打工的小李"）。
   读者记住的是人，不是术语。

2. **类比落地**
   "现收现付 = 传话游戏"、"三支柱 = 自来水/单位浴室/桶装水"、"行为偏差 = 大脑的快捷键"。
   类比的标准：让一个 12 岁的孩子也听懂。

3. **数据节制**
   全文 5–8 个最关键的数字。每个数字都必须服务叙事，不是炫技。
   一个对比性数字 > 三个并列性数字。

4. **反直觉对比要停下来强调**
   "同样的人、同样的福利、唯一变的就是默认勾选 → 37%→86%。"
   这种地方不要急着进入下一段，让读者在这里多停一秒。

5. **建造者口吻，不是观察者口吻**
   ❌ "X 制度的缺陷在于…"（这是观察者）
   ✅ "如果你是 1990 年的政策设计者，你会怎么搭这个东西？"（这是建造者）

6. **来源可追溯但不打断节奏**
   在涉及具体数据时用括号简标 `(详见 X.md)`，推理和类比标🔴。
   末尾给一段"素材来源"小节，把链路补全。

7. **收束回主干**
   最后一节必须明确说："所以我们这个研究要回答的问题是 [主干]。"
   绝对不要以"未来还需要进一步研究"收尾——那是综述报告，不是这个 skill 的产物。

### 反模式

- ❌ 第一句话是"近年来 X 问题日益突出..."——党八股，立刻死
- ❌ 大量定义、术语、英文缩写堆在前两段——读者还没找到立足点
- ❌ 章节之间只有逻辑关联没有情绪关联——读者会走神
- ❌ 数据出现时不解释"这意味着什么"——只是炫研究深度
- ❌ 不给收束——让读者自己琢磨"所以呢"

### 产物

一篇 1500–3500 字的费曼式研究综述。
**自带主干、自带演变、自带数据、自带对照、自带闭环。**
可以直接喂给团队/老师/同事，不需要补充材料。

## 全流程质量自检清单

完成全流程后，逐条勾：

**拆解**
- [ ] 子板块覆盖了演进 / 现状 / 各方行为 / 受众态度 / 对照（缺一项要解释为什么不需要）
- [ ] 子板块互相独立，没有"B 必须等 A 完成"的依赖
- [ ] 用户对拆分方案点头了

**并研**
- [ ] 所有 subagent 都用了 mcp__research__search 并按板块类型选了合适引擎
- [ ] 学术类板块用了 openalex/crossref/arxiv，不是只靠网页搜索
- [ ] 每份产物有🟢🟡🔴 标注、有来源清单
- [ ] 核心数字至少 2 源验证（1 源的明确标"仅 1 源"）
- [ ] subagent 没把整篇文档复制回主对话（context 干净）

**蒸馏**
- [ ] 主干能用一句话（≤80 字）说清楚
- [ ] 主干不是"我们要分析 X"这种空话
- [ ] 用户对主干点头了

**讲述**
- [ ] 全文从"为什么世界需要这东西"开始，不是从定义开始
- [ ] 每个抽象段后面都有具体角色/场景
- [ ] 关键数据控制在 5–8 个
- [ ] 反直觉对比有专门停顿强调
- [ ] 末尾回到主干，闭环
- [ ] 没有"未来需进一步研究"这种烂尾

## Skill 调用示例

**用户输入**：
> 我们小组要做一个 X 主题的研究/报告，主要回答 [大概方向]。

**Skill 行为序列**：

1. **澄清阶段**：用 AskUserQuestion 提 1–2 个关键决策（如要不要国际对比、输出形式）
2. **拆解阶段**：给出 3–6 个子板块的清单 + 每个的一句话定位，等用户确认
3. **并研阶段**：建对应的 TaskCreate，给每个子板块派 subagent（run_in_background），等全部回来
4. **蒸馏阶段**：读完 summary 后给出主干句，等用户确认
5. **讲述阶段**：按 8 层结构写出完整研究综述，落到对话里 + 选择性落到桌面文件

每一步用户都可以打断、调整、回退。这个 skill 的价值不在自动化，而在结构化——用户全程知道我在哪一步、产物在哪儿、为什么要这样做。

---

## 适用边界

**这个 skill 擅长**：
- 公共政策/制度类研究（养老金、教育、医保、税收）
- 行为现象研究（为什么 XX 群体不/会做 YY）
- 技术/产品演变研究（一个东西怎么变成今天这样）
- 跨学科综述（需要整合多源、对照国际经验）

**这个 skill 不擅长**：
- 纯理论推导（数学、物理、形式逻辑）
- 实时数据 / 当下决策（股票预测、突发事件）
- 单点事实查询（用普通搜索就行，别杀鸡用牛刀）
- 创意性写作（小说、诗歌、营销文案）
- 代码/工程问题（用 Plan 或 explore agent）
